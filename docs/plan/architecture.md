# Codebase map

Terse orientation for a cleared/compacted Worker — read once, skim per dispatch.
One line per entry. Verified against the tree; refreshed at each phase close.
Deeper rules live in `conventions.md`; task status in `.herdsman/state.md`.

## Top-level layout

- `core/` — package `olf_core`, **pure Dart, no Flutter, no `DateTime.now()`**. Date math, cycle engine, predictors, repositories (interface + drift impl), DB schema + migrations.
- `app/` — package `olf_app`, Flutter. Screens/widgets (Riverpod), encrypted DB layer, platform channels, notification scheduling, a11y test harness.
- `.github/workflows/` + `.github/scripts/` — CI gates (see below).
- `docs/plan/` — this plan set. `requirements.md` (root) — the spec. `scripts/cut_release.sh` — release cut.
- `core/**/*.g.dart` — committed drift codegen; CI fails if stale.

## core/ modules (`core/lib/src/`)

- `date_math.dart` — day arithmetic, `dateOnly`, `daysBetween`. The clock is always injected.
- `cycle/` — `cycle_derivation.dart` (`deriveCycles`, `CycleStats`, `CycleRegularity`), `cycle_phase.dart` (`cyclePhase`), `pregnancy_event.dart` (`PregnancyEndKind`, `mostRecentPregnancyEnd`, `pregnancyRecoveryState`).
- `prediction/` — **seam: `predictor.dart` `abstract interface class Predictor` → `CyclePrediction`** (the value object gained an additive `copyWith` in p8.5). `robust_predictor.dart` (v1), `adaptive_predictor.dart` (`AdaptivePredictor implements Predictor`, v2 correctable, same seam), `prediction_delta.dart`, `date_range.dart`.
- `wearable/` — p8.5 passive inference. `passive_phase_inference.dart` (`inferPassivePhase({temperatures, cycles, prediction, today, hrv, sleep}) → PassivePhaseEstimate?` — pure, `today`-injected; one-sided `enum PassivePhaseRead {ovulationLikelyPassed}` + coarse `enum PassiveConfidence {low,medium,high}`; picks one temperature track (basal ≥9 readings else `sleepingWrist`, never blended), reuses p7.3 `thermalShift`, honest `null` on thin signal; `PassiveHrvSample`/`PassiveSleepSample` accepted but **not consumed** — HRV/sleep ingestion is a later follow-up). `passive_informed_predictor.dart` (`PassiveInformedPredictor implements Predictor` — decorator: re-anchors **only** `fertileWindow` on a confirmed current-cycle shift, every next-period field passed through verbatim; no passive data → byte-identical to `inner`). See `docs/passive-phase-inference.md`.
- `backtest/` — `backtest_harness.dart`, `backtest_metrics.dart`, `synthetic_history.dart`, `synthetic_passive_signal.dart` (p8.5 — `syntheticPassiveTemperature(history)`, a deterministic seeded passive-temp track per profile; scores `PassiveInformedPredictor` for no MAE/coverage/ovulation-error regression), `correction_response.dart` (Phase 3 calibration; not shipped in-app).
- `db/` — `app_database.dart` (drift `AppDatabase`, **`schemaVersion => 11`**, `MigrationStrategy get migration`), `tables.dart` (incl. `enum CycleEventType {periodStart, pregnancyLoss, birth}`; `PainEntries` + `enum PainRegion` since v8, p7.5; `PmddRatings` + `enum PmddSymptom` + `pmddSymptomLabel()` since v9, p7.6; `bbt_entries.measurementKind` TEXT NOT NULL DEFAULT `'basal'` + `enum BbtMeasurementKind {basal, sleepingWrist}` since v10, p8.1a; `daily_flows.sourceDevice` + `bbt_entries.sourceDevice` nullable TEXT since v11, p8.2 — free-form wearable tag, provenance only, cleared on in-app edit), `database_key_store.dart`, `app_database.g.dart`. Migrations v1–v11: v2–v6 additive `createTable`, v7 (p6.1) first ALTER (`source`/`external_id` cols, `to >= 7` guarded), v8 (p7.5) additive `pain_entries`, v9 (p7.6) additive `pmdd_ratings` (PK `{date, item}`), v10 (p8.1a) ALTER add `bbt_entries.measurement_kind` (`from < 10 && to >= 10`, inner `from >= 5`), v11 (p8.2) ALTER add `source_device` to `daily_flows` + `bbt_entries` (`from < 11 && to >= 11`, inner `from >= 3` / `from >= 5`).
- repositories — pattern: `<x>/<x>_repository.dart` (interface) + `<x>/drift_<x>_repository.dart` (impl). Covers `symptom/`, `settings/` (`app_settings` KV — typed-key seam for mode flags etc.), `meds/`, `mucus/`, `bbt/`, `flow/`, `period/`, `reminders/`, `repository/` (cycle events), `pain/` (`PainEntry` per-day endometriosis pain/flare log — rejects `SymptomSeverity.none`, note cap `kPainNoteMaxLength`, p7.5), `pmdd/` (`pmdd_rating_repository.dart` + `drift_pmdd_rating_repository.dart` — `PmddRating` one row per symptom per day; `rateDay(date, Map<PmddSymptom,SymptomSeverity>)` transactional diff-write, `none` **is** stored = "rated, nothing today", p7.6).
- `symptom/symptom_severity.dart` — pure `enum SymptomSeverity {none,mild,moderate,severe}` (`.rank` 0–3, `.label`, `.ordered`) — olf's first ordered symptom scale; stored by name in `pain_entries.intensity` (p7.5, never `none`) and `pmdd_ratings.rating` (p7.6, `none` stored) — reused verbatim, no change at v9.
- `health/` — **interop seam: `health_platform_gateway.dart` `abstract class HealthPlatformGateway`**. `health_sample.dart` (`HealthSampleType` + `olf/health` wire tokens; `wristTemperature` lit up on iOS since p8.1a — `sleep`/HRV still declared-but-unmapped, → p8.5; `HealthSample`/`LocalSampleView` carry a plain `bool isSleepingWrist` since p8.6, set app-side from the p8.1a `measurement_kind`, consumed only by the precedence classifier — never a matching key), `source_precedence.dart` (p8.6 — pure `sourcePrecedenceTier({source, isSleepingWrist, sourceDevice}) → enum SourcePrecedenceTier {genericPlatform(0), sleepingWrist(1), attributedDevice(2), manual(3)}`; total order, `outranks` / `compareTiers`), `known_devices.dart` (p8.6 — the recognised-vendor registry `knownDevicePackagePrefixes` + `knownDevicePlainNames` → `knownVendorLabel` / `isAttributedDevice`; **moved here from `app/device_label.dart`** so the prettifier and the classifier share one table), `import_reconciler.dart` (pure reconcile engine: `externalId` then `(type, day)`; manual-value disagreement is always a conflict — **unchanged by p8.1a**: wrist temp is re-typed to `basalBodyTemperature` app-side at the reconcile boundary so it competes for the day slot. **p8.2 added one additive clause:** `sourceDevice` on `HealthSample`/`LocalSampleView`; `inserts` indexed into `byTypeDay` as they accumulate; a `(type,day)` match same `source` + two different recognised `sourceDevice` + values beyond `tolerance` → `ConflictReason.crossDeviceDisagreement`. **p8.6 layered precedence on top:** a cross-tier same-`source` disagreement auto-resolves — higher tier → `ReconciliationUpdate`, lower tier → new `ReconciliationSupersede` bucket (dropped, not surfaced, not counted); an accepted reading (insert *or* update) becomes the slot's running winner for the rest of the pass; a same-tier two-recognised-device dispute stays `crossDeviceDisagreement` and *withdraws* any auto-update already emitted for that slot ("no blind update"); 3+ same-tier disagreements fold into one conflict via `ReconciliationConflict.alsoContending`. `manual` is never auto-resolved. No schema change (§5 option (a) — the loser stays in the OS health store). Single-source behaviour byte-for-byte unchanged, regression-locked).
- `export/` — `clinical_report.dart` (pure `ClinicalReport` + `buildClinicalReport`, `generatedOn` injected) — doctor PDF is built app-side.
- `modes/` — Phase 7 life-stage modes. `life_stage_mode.dart` (`enum LifeStageMode` p7.1–p7.8, each owns `app_settings` key `mode.<name>`), `postpartum_cycle_return.dart` (pure derivation, p7.1), `gestational_age.dart` (pure GA maths — `PregnancyStartReference.lmpAnchor` is the one conversion seam for LMP/dueDate/conception, p7.2a), `pregnancy_week_notes.dart` (bundled wk 0–42 copy, p7.2a), `daily_fertility_score.dart` (`dailyFertilityScore(...)` — TTC score layered on the p3 estimate + BBT/mucus, no second engine, p7.3), `birth_control_recalibration.dart` (`deriveBirthControlRecalibration(...)` + `BirthControlMethodHormonal.isHormonal` — withhold-the-forecast read, p7.8), `perimenopause_transition.dart` (`derivePerimenopauseTransition({periods, today})` → `PerimenopauseTransitionRead?` — pure variability-trend + descriptive stage read over `deriveCycles`/`CycleStats`/gap logic; output is two enums + plain facts, **NO numeric score — §9(12)**; predictor untouched, p7.7), `endometriosis_events.dart` (`painFlareEvents(Iterable<PainEntry>) → List<PhaseEvent>` — `'Pain'` every logged day, `'Flare'` also on flare days; the only new mapping, feeds the correlation core, p7.5), `pmdd_overlay.dart` (`pmddOverlay({ratings, cycles, today}) → PmddOverlay` — feeds `'rated'` per rated day + `'notable'` (≥ `moderate`) per notable day into `cyclePhaseCorrelations` unchanged; `PmddLutealRead` enum, `runsHigherInLuteal` iff notable `showsUpMostIn == luteal`; **NO numeric score / DRSP / threshold — §9(12)**, p7.6), **`cycle_phase_correlation.dart` — the reusable correlation core: `PhaseEvent{day,category}` → `cyclePhaseCorrelations({events,cycles,today})` → `List<PhaseCorrelation>`; descriptive only (rate-normalised concentration, no p-values); p7.5–p7.7 parameterise it (p7.4)**.
- `cycle/cycle_phase.dart` — `currentCyclePhase(...)` (p1.12) + **`cyclePhaseTimeline(cycles,{today})`** — retrospective per-cycle phase segments anchored on real logged next-period dates; the input to `cyclePhaseCorrelations` (p7.4). `bbt/thermal_shift.dart` — retrospective `thermalShift(...)` ovulation-confirmation primitive (p7.3, not a forecaster). Every `bbt_entries` temperature reader filters `measurementKind == basal` since p8.1a (zero behaviour change from a stored `sleepingWrist` row): `thermalShift`, `dailyFertilityScore`, `bbt/bbt_chart.dart`, `export/clinical_report.dart` temp series, `reminders/drift_logging_activity_repository.dart`.
- `security/` — `auto_lock.dart`, `pin.dart`, `pin_store.dart`. `backup/` — `backup_cipher.dart`, `backup_document.dart`, `backup_service.dart` (encrypted export/restore). `retention/` — `retention_service.dart`, `retention_window.dart` (auto-delete). `personalization/pronouns.dart`, `a11y/` (`captions.dart`, `contrast.dart`).

## CI gates

- `ci.yml` (checks aggregate to **`CI OK`**): Detect workspace · Format (`dart format --set-exit-if-changed`) · Analyze (`--fatal-infos --fatal-warnings`, incl. committed-codegen-current) · Test (core units + app widget) · **Dependency audit** (`.github/scripts/dependency_audit.dart` — dep denylist, no ad/analytics SDK, Android permission diff, transport-security assertions; also fails on stale `pubspec.lock`) · Build (macos→iOS, ubuntu→APK, + install-size §3) · **Perf budget** (`apk_size_budget.dart` vs baseline; `cold_start_budget.dart`).
- `nightly-integration.yml` — `integration_test/` on a real Android emulator (matrix API level) + iOS simulator.
- `dependency-report.yml` — scheduled dep-graph report. `release.yml` — tag → signed build.
- Branch protection: `main` requires a PR + green `CI OK`; no bypass. The Orchestrator cannot direct-push (see `.herdsman/state.md` push policy).
